# ChronoBrush · 全分辨率双关键帧补帧

这个仓库是参考帧驱动笔触重建的无 MP4 版本。原视频只在本地预分析阶段读取。发布后的页面和独立资源包由 19 张 1470×630 全分辨率 WebP 关键帧、271 张紧凑双向光流格、运动掩膜、静态基底和 JSON 时间轴组成。运行时由时间轴计算帧号，分别把前后两张关键帧形变到当前时刻，再以连续权重混合，最后按同一时刻的状态绘制椭圆、线段、贝塞尔和笔触。静态区域继续来自锁定的 WebGL 基底。

## 连续补帧与体积

上一版每帧只选用最近的关键帧。锚点切换时关键帧和光流路径同时更换，因而产生可见跳变；离线测得最大帧间变化为 `4.0614`。当前版本为锚点之间的每一帧保存两路光流：当前帧到前一关键帧、当前帧到后一关键帧。shader 分别采样两次并按时间线性混合，权重从 0 连续增长到 1；精确关键帧复用一个零位移光流格。这样锚点边界没有硬切换，也不需要为每帧增加全分辨率颜色图。

光流图采用 q92 有损 WebP，关键帧采用 q95 有损 WebP；离线评估直接读取 WebP 解码后的像素，因此解码误差已经计入下列指标。压缩档位由 `analysis/compression_sweep.json`、`analysis/compression_sweep2.json` 和对应结果文件比较得到，生产资源由 `tools/verify_assets.py` 再次验证。

| 指标 | 上一版最近锚点 | 当前双向补帧 |
| --- | ---: | ---: |
| 资源包 ZIP | 7,536,697 B | **5,592,824 B** |
| MAE | 2.2101 | 2.4105 |
| PSNR | 36.158 dB | 35.364 dB |
| 清晰度梯度 | 7.3532 | 6.9138 |
| 原视频清晰度参考 | 7.6851 | 7.6851 |
| 最大帧间变化 | 4.0614 | **2.8099** |
| 平均帧间变化 | 1.5872 | **1.5875** |
| 锚点切换平均变化 | 1.3151 | 1.5082 |
| 锚点切换尖峰比 | 0.9456 | 0.9603 |

双 warp 混合会让中间帧有轻微软化，这是用 19 张颜色帧换取连续运动和小体积的代价。资源包仍比上一版小约 25.8%，且没有增加关键帧数量。

## 本地运行

```bash
npm install
npm run dev
```

`npm test` 验证时间轴映射、状态插值、双光流格坐标、混合权重和资源文件；`npm run build` 生成 `docs/` 静态站点。

## 资源数据

`public/assets/` 和独立压缩包 `chronobrush-runtime-assets.zip` 都只包含这 5 个文件：

| 文件 | 用途 |
| --- | --- |
| `base.webp` | 锁定的 WebGL 静态基底，初始化后不更新 |
| `keyframes.webp` | 19 张 1470×630 全分辨率关键帧，4 列 × 5 行贴图集 |
| `flow.webp` | 271 张 368×158 量化光流格，13 列 × 21 行贴图集 |
| `motion-mask.webp` | 运动区域掩膜，决定静态基底与当前重建画面的混合 |
| `timeline.json` | 96 条绘图指令、逐帧颜色、位移、旋转、形变，以及双向光流格和补帧权重 |

`timeline.json` 中每条指令都有 4 个控制点、绘制宽度以及 145 个状态。`src/timeline.js` 按时间查找状态并插值；`src/draw.js` 调用绘图函数；`src/reference.js` 在着色器里解码两路光流、采样两张全分辨率关键帧、连续混合并与静态基底合成。所有贴图在初始化时上传一次，播放过程中只切换格子坐标、混合权重和帧状态，不上传新纹理，也不读取任何视频文件。

重新生成资源和资源包：

```bash
python -m pip install opencv-python-headless numpy pillow
python tools/build_assets.py --video "参考.mp4" --out public/assets
python tools/build_sparse_assets.py --video "参考.mp4" --out public/assets
python tools/verify_assets.py --video "参考.mp4"
python package_assets.py
```

生成命令需要本地原视频，产出的资源目录、ZIP 和网页运行时均不含 MP4。校验清单为 `chronobrush-runtime-assets.sha256.json`。

## 还原边界

关键帧本身保持 1470×630 分辨率，因此静态细节和边缘明显比低清放大版清晰。中间帧由双向光流形变并混合得到，复杂遮挡和新出现的区域仍可能有轻微拖影；指令层是展示每条笔触运动参数的半透明诊断层，可以关闭。若要严格逐像素保存每一帧，需要完整帧数据或视频流，但那会重新带来几十 MB 的资源体积或 MP4 依赖。此版本在缩小资源包的前提下保留 24 fps 时序动画、连续补帧和接近参考的细节清晰度。
