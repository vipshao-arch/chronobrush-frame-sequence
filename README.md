# ChronoBrush · 全分辨率稀疏关键帧 + 光流

这个仓库是参考帧驱动笔触重建的无 MP4 版本。原视频只在本地预分析阶段读取。发布后的页面和独立资源包由 19 张 1470×630 全分辨率 WebP 关键帧、145 张紧凑光流图、运动掩膜、静态基底和 JSON 时间轴组成。运行时由时间轴计算帧号，选择最近的关键帧，用当前帧的量化光流在 WebGL 中形变到对应时刻，再按同一时刻的状态绘制椭圆、线段、贝塞尔和笔触。

## 在线查看

<https://vipshao-arch.github.io/chronobrush-frame-sequence/>

页面提供播放、逐帧步进、拖动时间轴、指令层开关、左右分屏对比，以及核心画面和叠加笔触的 MAE 读数。右侧对比画面是全分辨率重建参考，左侧保留锁定的 WebGL 静态基底。

## 为什么使用稀疏关键帧

上一版把 145 帧保存为 735×315 的低清贴图格，显示时放大到 1470×630，因此文字和边缘发虚。若把 145 帧全部保存为高质量全分辨率 WebP，资源会增长到约 27–35 MB，无损版本约 89 MB。

当前方案把参考数据拆成两类：少量高分辨率颜色关键帧，以及每帧一张 368×158 的运动光流图。光流只描述像素位移，体积很小；中间帧不靠低清图放大，而是从全分辨率关键帧形变得到。每帧对应最近锚点，最远相差 4 帧。播放仍是 24 fps 的逐帧状态，静态基底初始化后不更新。

在 15 个均匀采样帧上，离线对比原视频的实测结果：

| 指标 | 145 帧低清贴图格 | 19 张全分辨率关键帧 + 145 张光流 |
| --- | ---: | ---: |
| MAE | 3.1191 | 2.2101 |
| PSNR | 32.708 dB | 36.158 dB |
| 清晰度梯度 | 5.5793 | 7.3532 |
| 原视频清晰度参考 | 7.6851 | 7.6851 |

关键帧与光流贴图合计约 6.16 MB；完整的 5 个运行时数据文件约 9.27 MB，ZIP 压缩后 7.54 MB，比上一版 9.82 MB 资源包更小。评估数据见 `analysis/sparse_uniform_8_flow368.json`，离线质量校验见 `analysis/quality.json`。

## 本地运行

```bash
npm install
npm run dev
```

`npm test` 验证时间轴映射、状态插值、稀疏贴图坐标和资源文件；`npm run build` 生成 `docs/` 静态站点。

## 资源数据

`public/assets/` 和独立压缩包 `chronobrush-runtime-assets.zip` 都只包含这 5 个文件：

| 文件 | 用途 |
| --- | --- |
| `base.webp` | 锁定的 WebGL 静态基底，初始化后不更新 |
| `keyframes.webp` | 19 张 1470×630 全分辨率关键帧，4 列 × 5 行贴图集 |
| `flow.webp` | 145 张 368×158 量化光流图，13 列 × 12 行无损贴图集 |
| `motion-mask.webp` | 运动区域掩膜，决定静态基底与当前重建画面的混合 |
| `timeline.json` | 96 条绘图指令、逐帧颜色、位移、旋转、形变，以及关键帧锚点映射 |

`timeline.json` 中每条指令都有 4 个控制点、绘制宽度以及 145 个状态。`src/timeline.js` 按时间查找状态并插值；`src/draw.js` 调用绘图函数；`src/reference.js` 在着色器里解码光流、采样全分辨率关键帧并混合静态基底。所有贴图在初始化时上传一次，播放过程中只切换格子坐标和帧状态，不上传新纹理，也不读取任何视频文件。

重新生成资源和资源包：

```bash
python -m pip install opencv-python-headless numpy pillow
python tools/build_assets.py --video "参考.mp4" --out public/assets
python tools/build_sparse_assets.py --video "参考.mp4" --out public/assets
python tools/verify_assets.py --video "参考.mp4"
python package_assets.py
```

生成命令需要本地原视频，产出的资源目录、ZIP 和网页运行时均不含 MP4。校验清单为 `chronobrush-runtime-assets.sha256.json`。

## 还原边界

关键帧本身保持 1470×630 分辨率，因此静态细节和边缘明显比低清放大版清晰。中间帧由光流形变得到，复杂遮挡和新出现的区域仍可能有轻微拖影；指令层是展示每条笔触运动参数的半透明诊断层，可以关闭。若要严格逐像素保存每一帧，需要完整帧数据或视频流，但那会重新带来几十 MB 的资源体积或 MP4 依赖。此版本在体积基本不增加的前提下保留了 24 fps 时序动画和接近参考的细节清晰度。
